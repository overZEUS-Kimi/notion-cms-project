# 개인 개발 블로그 개발 로드맵

> 💡 본 로드맵은 올바른 개발 순서에 따라 체계적으로 진행되는 개발 계획입니다.

---

## 📋 개발 순서 원칙

1. **프로젝트 초기 설정** → 모든 개발의 기반 마련
2. **공통 모듈/컴포넌트** → 재사용 가능한 기반 구축
3. **핵심 기능** → 블로그의 필수 기능 구현
4. **추가 기능** → 사용자 경험 향상
5. **최적화 및 배포** → 성능 및 배포 완성

---

## Phase 1: 프로젝트 초기 설정 (골격 구축)

### 📝 작업 사항

- [ ] Next.js 15 프로젝트 생성 및 초기 설정
- [ ] TypeScript 설정 및 tsconfig.json 구성
- [ ] Tailwind CSS 설정 (tailwind.config.ts)
- [ ] shadcn/ui 초기화 및 컴포넌트 설치
- [ ] Lucide React 아이콘 설정
- [ ] 환경 변수 설정 (.env.local, .env.example)
  - `NOTION_API_KEY`
  - `NOTION_DATABASE_ID`
  - `NEXT_PUBLIC_SITE_URL`
- [ ] 프로젝트 기본 디렉토리 구조 생성
  ```
  src/
  ├── app/
  ├── components/
  ├── lib/
  │   ├── notion.ts
  │   └── types.ts
  ├── styles/
  └── utils/
  ```
- [ ] Git 저장소 초기화 및 .gitignore 설정

### 🤔 왜 이 순서인가?

프로젝트 전체의 기반이 되는 구조와 개발 환경입니다. 이 단계를 제대로 완료하지 않으면 이후 모든 개발이 비효율적으로 진행됩니다.

### ⏱️ 예상 소요 시간

**2-3일** (30분 ~ 1시간)

### ✅ 완료 기준

- Next.js 개발 서버가 정상적으로 실행되고 localhost:3000에서 기본 페이지 표시
- TypeScript 설정이 완료되고 타입 체크에 에러 없음
- Tailwind CSS와 shadcn/ui가 정상 작동하고 스타일이 적용됨
- 모든 환경 변수가 .env.local에 설정되어 있음

## Phase 2: 공통 모듈/컴포넌트 개발

### 📝 작업 사항

**A. 타입 및 인터페이스 정의**
- [ ] Notion 데이터 모델 타입 정의
  ```typescript
  // BlogPost, Category, Tag, NotionBlock 등
  ```
- [ ] API 응답 타입 정의
- [ ] Props 인터페이스 정의

**B. Notion API 유틸리티 작성**
- [ ] Notion 클라이언트 초기화 함수 (`lib/notion.ts`)
- [ ] 데이터 조회 함수
  - `getAllPosts()`: 전체 글 목록 조회 (발행됨 상태만)
  - `getPostBySlug()`: 개별 글 상세 조회
  - `getAllCategories()`: 카테고리 목록 조회
  - `getPostsByCategory()`: 카테고리별 글 조회
  - `searchPosts()`: 검색 함수
- [ ] 데이터 변환 함수 (Notion → 앱 형식)

**C. 레이아웃 및 기본 컴포넌트**
- [ ] Header 컴포넌트
  - 로고 / 사이트 제목
  - 검색 바
  - 카테고리 네비게이션
- [ ] Footer 컴포넌트
  - 저작권, 소셜 링크 등
- [ ] Layout 래퍼 컴포넌트
- [ ] 메타데이터 설정 유틸리티

**D. 재사용 컴포넌트**
- [ ] BlogCard 컴포넌트 (글 카드)
- [ ] BlogCardGrid 컴포넌트 (글 목록)
- [ ] Pagination 컴포넌트
- [ ] TagBadge 컴포넌트
- [ ] CategoryFilter 컴포넌트

### 🤔 왜 이 순서인가?

타입 정의와 Notion API 연동 로직을 먼저 구축하면, 이후 페이지 개발에서 이 모듈들을 그대로 사용할 수 있습니다. 중복 개발을 방지하고 유지보수성을 높입니다.

### ⏱️ 예상 소요 시간

**3-5일** (2-3시간)

### ✅ 완료 기준

- Notion API 호출이 정상 작동하고 데이터를 정확하게 조회
- 모든 컴포넌트가 스토리북 또는 테스트 페이지에서 정상 렌더링
- TypeScript 타입 체크에 에러 없음
- 컴포넌트 Props이 명확하게 정의되어 있음

## Phase 3: 핵심 기능 개발

### 📝 작업 사항

**A. 글 목록 페이지 (/)**
- [ ] 홈 페이지 구현
  - 발행된 글 목록 표시 (최신순)
  - 글 카드 그리드 레이아웃
  - 검색 바 통합
  - 카테고리 필터 (사이드바 또는 탭)
- [ ] 페이지 메타데이터 설정 (메타 태그, Open Graph)
- [ ] SSG 설정 (build time에 정적 생성)

**B. 글 상세 페이지 (/posts/[slug])**
- [ ] 동적 라우트 설정 (`/posts/[slug]/page.tsx`)
- [ ] 글 제목, 발행일, 카테고리, 태그 표시
- [ ] Notion 블록 렌더링 구현
  - 텍스트 블록
  - 제목 블록 (h1, h2, h3 등)
  - 이미지 블록
  - 코드 블록 (syntax highlighting 포함)
  - 리스트 블록
  - 인용문 블록
- [ ] 이전/다음 글 네비게이션
- [ ] 글 공유 기능 (선택)
- [ ] 페이지 메타데이터 동적 설정
- [ ] ISR 설정 (주기적 재생성)

**C. 정적 페이지 생성 설정**
- [ ] `generateStaticParams()` 함수 구현
- [ ] ISR 재검증 시간 설정 (예: 3600초)
- [ ] 빌드 최적화

### 🤔 왜 이 순서인가?

글을 조회하고 표시하는 기능은 블로그의 핵심입니다. 이 기능이 완성되어야 사용자가 블로그를 방문할 수 있습니다.

### ⏱️ 예상 소요 시간

**5-7일** (4-5시간)

### ✅ 완료 기준

- 홈 페이지에서 Notion 데이터베이스의 발행된 글이 정상 표시
- 글 상세 페이지에서 모든 기본 Notion 블록이 정상 렌더링
- SSG/ISR이 정상 작동하고 정적 페이지가 생성됨
- 페이지 로딩 시간이 2초 이내
- 메타데이터가 정상적으로 설정되어 SEO 기본 요구사항 충족
